# Debug & Observability

How to observe client behavior: debug logging and rate limit info.

## Debug logging

Set `config.debug` when creating the client to log each request (start, complete, error) to the console:

```typescript
const client = new PcoClient({
  auth: { /* ... */ },
  debug: true
});
```

For more control, use an options object:

```typescript
const client = new PcoClient({
  auth: { /* ... */ },
  debug: {
    prefix: '[PCO]',
    includePayloads: false,
    onLog: (message) => myLogger.debug(message)
  }
});
```

- **`prefix`**: Prepended to each log line (e.g. `[PCO]`).
- **`includePayloads`**: When `true`, logs request/response payloads (noisy).
- **`onLog`**: Custom sink; if omitted, logs go to `console.debug`.

No other setup is required. The HTTP layer logs request start, completion, and errors when `debug` is set.

## Rate limit info

To inspect current rate limit state (e.g. in a health check), use `getRateLimitInfo()`:

```typescript
const info = client.getRateLimitInfo();

console.log(`Remaining: ${info.remaining}/${info.limit}`);
console.log(`Window resets in: ${info.windowResetsIn}ms`);
```

- **`remaining`**: Requests left in the current window.
- **`limit`**: Max requests per window (typically 100).
- **`windowResetsIn`**: Milliseconds until the window resets.

Use this to throttle or delay work when `remaining` is low, or to log rate limit status.

## Error handling

For monitoring errors, wrap calls in try/catch and use `PcoApiError` (check `error.status`). See the [Error Handling Guide](./error-handling.mdx).
